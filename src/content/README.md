# お知らせ・プレスリリースの投稿手順

このディレクトリに `.md` ファイルを1つ足すだけで、次のすべてに自動で載ります。
**コードを書き換える必要はありません。**

| 置き場所 | 載る場所 |
| --- | --- |
| `news/<ファイル名>.md` | ニュース一覧 `/company/news` |
| `press/<ファイル名>.md` | プレスリリース一覧 `/company/press` |

どちらも、静的HTML（JSを実行しないAIクローラー向けのプリレンダ）と
RSS `/feed.xml` にも自動で入ります。

## 手順

1. `news/` か `press/` に `<年>-<月>-<内容>.md` を作る（例: `2026-10-launch.md`）。
   ファイル名がそのまま一覧ページ内のアンカーID（`/company/news#2026-10-launch`）に
   なるので、英小文字・数字・ハイフンで書く。**先頭は必ず数字**。
2. 下の書式で中身を書く。
3. コミットしてプッシュする。デプロイされれば公開される。

## 書式

ニュース（`news/`）:

```md
---
date: "2026-10-01"        # 必須。YYYY-MM-DD または YYYY-MM
category: "お知らせ"        # 必須。お知らせ / プレスリリース / メディア / 採用
title: "〜しました"         # 必須。見出し
description: "〜。"        # 必須。一覧に出る本文（1〜3文）
---
```

プレスリリース（`press/`）は `category` を書きません。それ以外は同じです。

- **日が分からない出来事は月まで**（`"2025-10"`）で書く。
  表示は「2025年10月」になり、日まで書けば「2025年10月1日」になる。
  分からない日を埋めない。
- 並び順は `date` の新しい順。ファイル名順ではない。

## 気をつけること

- **書いていないことは書かない。** 実績・数値・メディア掲載・受賞は、
  出典を示せるものだけ。このサイトは 2026年Q3 ローンチ予定の準備中サービスで、
  利用者数や施工実績はまだ存在しない。
- `date` は実際に起きた日。未来の日付は書かない。
- 記事ページ（1件ごとのURL）は作っていません。1〜3文の告知でページを量産すると、
  検索エンジンに中身の薄いページと見なされるためです。長文の発表を出したくなったら、
  そのときに記事ページを追加します。

## 書式を間違えたら

`npm run check:seo` が落ちて、どのファイルの何が足りないかを教えます。
ビルド（`npm run build`）も同じパーサを通るので、壊れたまま公開されることはありません。
